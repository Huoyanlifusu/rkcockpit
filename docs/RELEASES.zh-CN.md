# 发布策略

[English](RELEASE.md)

## 版本规则

rkcockpit 遵循语义化版本规范，当前采用 `0.x.y` 系列：

- `0.MINOR.0`：向后兼容的新功能或重要改进
- `0.MINOR.PATCH`：向后兼容的缺陷与安全修复
- `1.0.0`：首个明确承诺公共接口稳定的版本

自 `1.0.0` 起，`MAJOR` 版本可包含不兼容变更。

## 发布节奏

版本以就绪状态为准。补丁版本按需发布，次版本目标节奏为 4–8 周。涉及重要的认证、
存储、部署、传输或迁移变更时，应先发布候选版本。

以上节奏是目标，并非发布保证。

## 分支与标签

- `dev` 是集成分支，功能和修复拉取请求以其为目标。
- 发布拉取请求将经过测试的变更从 `dev` 提升至 `main`。
- `main` 包含稳定且可发布的代码。
- 稳定版本从 `main` 创建附注格式的 `vX.Y.Z` 标签，并对应一个 GitHub Release。
- 热修复从 `main` 创建，并合并回 `dev`。

## 兼容性与支持

在 `0.x` 阶段，最新次版本会获得修复；较早的次版本和预发布版本仅提供尽力支持。

每个版本需说明已测试的 Python 版本、宿主操作系统、传输方式、浏览器、部署模式，
以及配置或数据迁移要求。未被 CI 覆盖的平台，除非另行验证，否则仅提供尽力支持。

## 发布检查清单

发布版本前：

1. 计划纳入的测试及 Python、JavaScript 语法检查通过。
2. 涉及路径、认证和部署的安全敏感测试通过。
3. 英文和中文文档保持同步。
4. 升级、迁移与回滚行为已完成审查。
5. 发布提交已存在于 `main`。

发布说明需包含用户可感知和破坏性变更、升级与回滚说明、安全修复、已知问题、
已测试平台、迁移要求，以及与上一版本的完整对比链接。
